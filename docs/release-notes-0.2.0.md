## 重點更新

本版補充前後端共通的依賴設計原則，並提供技術 Profile 適用指引。新增要求屬於 `0.2.0`，適用範圍與審查門禁已核准，不回溯適用於 `0.1.0`。

### 新增共通規範

- **C-10 ADP 無環依賴**：元件與模組的原始碼依賴不得形成直接或間接循環；判定須提供受檢範圍、依賴邊定義及完整循環路徑。
- **C-11 SDP 穩定依賴**：依賴應朝向較穩定的契約與元件，不以目錄名稱或近期修改頻率推定穩定度。
- **C-12 SAP 穩定抽象**：穩定擴充邊界以適當契約隔離易變實作，不強制所有類別新增介面，也不以介面數量判定合規。

詳見 [共通基準](../standards/common.md)。

### 後端適用指引

- 保留既有 `Controller → Service → DataAccess → Repository` 架構，不強制改採 DDD 四層，亦不取消既有 Service 介面。
- 外部 I/O 與易變策略依實際需求，由核心定義契約、基礎設施提供實作；純工具可保持具體實作。
- 生產程式碼全面禁止 `@Lazy`（含 `self`）；同類別交易與快取需求分別委派 `TransactionExecutor`／`CacheExecutor`。
- 新來源的完整 4-Tier DAG 條文未重新匯入；本版補充的已核准適用範圍與衝突／遷移影響見發布前審查紀錄。本說明不認證消費端程式碼已完成修訂。

詳見 [後端 Profile](../standards/backend.md)。

### 前端適用指引

- 將依賴原則適用於 Vue／TypeScript 元件、Service、Store、Hooks、Router 與 API 基礎設施。
- 保留既有外部請求流程，不新增 Store／Hooks 必經鏈，也不依目錄名稱固定分級。
- 共用 Utils、Types 與 API 傳輸基礎設施不得反向依賴具體頁面。
- 可使用 Props／Emits、函式簽名及 TypeScript 型別表達契約，不強制建立 Interface／Impl 成對樣板。

詳見 [前端 Profile](../standards/frontend.md)。

### 審查邊界

- 區分原始碼依賴與執行期控制流程；前端另須區分執行期 import 與 `import type`。
- ADP 與明確邊界違規須具備可重現證據；SDP／SAP 疑慮若缺乏具體影響證據，先列建議，不以「不夠抽象」直接阻擋。
- 改成事件或延遲載入不代表自動解耦，仍須交代契約、執行時機、錯誤傳遞與一致性。
- 本次未新增自動化架構門禁、套件或消費端品質工具設定。

### 發布、採用治理與工具防護

- 分離內容核准、正式發布與消費端採用；草案／預發布僅供隔離試採用。
- 相容性以合規契約判定：原本合規的實作若因新增要求不再合規，即屬不相容。`0.x` 次版可承載不相容變更，修訂版不得新增合規義務；`1.0.0` 起不相容變更升主版。
- 已發布版本及提交對應不可變；撤回停止新採用並通知既有採用端評估，不自動切版。
- 核准綁定候選內容，變更後重審受影響範圍；到期例外未續准即失效，只影響相關要求與實作範圍。
- 匯出器改為隔離候選準備：草案與預發布須加 `--preview`，正式版本也不直接更新有效路徑；`--update` 已停用。
- 已發布候選核對完整提交存在及列管檔案、catalog、檢查器與匯出器的提交內容；拒絕掩蓋有效快照異動，且不因無關本機異動而拒絕準備。
- 本次不實作自動採用切換；消費端依受控程序保存舊基準、驗證新基準，失敗保留或恢復舊版。歷史快照與檢查器不改寫。

## 採用與遷移影響

- 消費端仍鎖定正式版本 `0.1.0`；本版發布不取代目前有效快照，也不自動匯出或覆寫快照。
- 固定來源 `standards/*/master-*.md` 保留原文，不直接修補；補充條文不代表固定來源全文已更新。
- 後續採用前須審查新增依賴要求、`@Lazy` 限制及既有專案例外的影響，不將既有工具白名單自動視為核准例外。
- 本版按可能不相容的次版修訂準備：ADP 新強制要求、共用層依賴限制及新增的生產程式碼 `@Lazy` 全面禁令（含 `self`），均可能使舊合規實作不再合規；須逐項檢視或取得有效例外，不能用產品 API 未變來宣稱相容。`0.1.0` 固定來源未記載此完整禁令，不將補充來源的演進當成舊版已有條文。尚未執行消費端完整依賴分析、Maven／前端測試與遷移切換驗證。
- 正式升版須另行確認可信來源、不可變 commit、版本差異及消費端核准，依 [採用與發布治理](../governance/adoption.md) 執行。
