# 分離發布與採用，以合規契約定義相容性

工程規範的發布表示版本可供選用，不代表消費端已遷移；產品 API 未變也不代表規範要求相容。因此內容核准、版本發布與專案採用分別管理，以原本合規實作是否仍合規判定相容性。`0.x` 階段由次版承載不相容變更，修訂版不得新增合規義務；自 `1.0.0` 起由主版承載不相容變更。

相較將發布綁定首個消費端採用，獨立發布避免專案進度綁住規範演進，但必須明列未驗證的遷移影響。相較核准後允許預發布版本成為正式基準，預發布僅供隔離試採用，降低候選要求變動對既有合規判定的干擾。

已發布版本與提交對應不可變，修正另發新版；撤回停止新採用並觸發既有採用端評估，不自動替換內容或切換版本。隔離候選增加人工切換成本，但避免原位覆寫與部分更新被誤認為採用成功；正式匯出須核對指定提交內容，可信發布來源另行核對。離線完整性檢查不承擔遠端認證或撤回查詢。

既有正式快照不追溯改寫，新工具保留歷史格式驗證能力，新匯出與升版操作則遵守新防護。詳細核准、例外、通知與切換程序見 [採用與發布治理](../../governance/adoption.md)。此決策不代表工作草案已正式發布，也不授權 Git 操作或消費端升版。
