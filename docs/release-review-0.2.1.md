## 範圍與核准邊界

本版核准範圍為檢查器行長格式修正、必要回歸測試、版本清單及發布文件。發布透過集中庫修訂分支、PR 與正常合併進行；完成必要驗證與門禁後才建立新的 `0.2.1` tag 及正式 Release。權限或分支保護阻擋時停止，不繞過保護、不強制推送。

不新增規範義務，不變更固定來源、授權、消費端、既有 tag、歷史 Release 或既有版本文件；本版發布不授權消費端採用。審核證據由本紀錄、回歸測試與集中庫 PR／發布紀錄共同構成，不以既有版本核准自動推定新內容通過。

## 程式修正證據

`scripts/check_snapshot.py` 僅將原第 141 行的 SHA-256 表達式拆成多行，不抽出會提前求值的變數。原始位元組讀取及 `or` 短路順序不變。

- 原超長行：102 字元；修正後整份檢查器最長 93 字元，沒有超過 100 字元的實體行。
- 以 Python `ast.parse`／`ast.dump(include_attributes=False)` 比對本版與 `0.2.0`，語法結構完全一致。
- 新 checker SHA-256：`2722ef5c84653a9044449bc7bf9b06c8a41a9259f4ed6152efb363524a4f309d`。
- 新增行長回歸驗證只針對本檢查器，不將其擴張為新的跨專案治理要求。

checker 不新增為 catalog 的規範檔案項目，以維持原有清單結構；匯出器仍核對 checker 的提交位元組，並將其實際 SHA-256 寫入候選 manifest 的 `checker_sha256`。

## 回歸驗證

```powershell
python -m unittest discover -s tests -v
python scripts/check_snapshot.py --catalog catalog.json
git diff --check
```

Python 3.14 環境的 47 項單元測試通過，包含：

1. 既有原始位元組比對、換行異動拒絕、checker 雜湊不符、版本／Profile／來源驗證。
2. 正式發布門禁、草案／預發布不可冒充正式、隔離匯出及拒絕覆寫。
3. 新增本檢查器全部實體行不超過 100 字元的回歸驗證。
4. 新增來源路徑不符時，即使指定不存在的 checker 仍回報原有來源錯誤，不提前讀檔。
5. 新增 CLI 使用內含執行即拋錯內容的歷史 checker，核對可通過且位元組與修改時間不變，驗證 `--checker-file` 僅讀取、不執行。

提交後須再以實際合併 SHA，在暫存測試專案驗證 backend／frontend 正式候選匯出、重複匯出與 `--require-published`；不以模擬提交取代此發布檢查，也不在真實消費端執行。結果於正式 Release 與交付摘要列明。

## 提交與發布對應

清單整體版本為 `0.2.1`；門禁與最終內容核對完成後狀態才轉為 `published`。清單的 commit 維持 `null` 以避免提交自身 SHA 循環；實際正式版本對應以 `0.2.1^{commit}` 的完整 SHA 及可信遠端 tag 核對。候選 manifest 必須由匯出器寫入真實提交，不使用虛構 SHA。
