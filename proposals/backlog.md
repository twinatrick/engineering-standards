# 工程改善提案盤點

以下全部為**待使用者核准**，不是本次新增強制規範；沒有修改業務、工具、CI 或 hooks。成本是初步相對估計，需在個別提案落地前細估。

## 優先處理

| ID／主題 | 問題與效益、證據 | 範圍／擬定等級 | 驗證方式 | 成本／遷移影響 |
| --- | --- | --- | --- | --- |
| P-01 既有規範一致化 | CF-01–03 與舊 API 範例會造成錯誤審查；統一適用語意 | 兩端；修正既有要求，實質收緊另核准 | 核對實際類別、例外案例、文件連結與審查測試 | 低至中；來源修訂後重新發布／採用，不能只改本地快照 |
| P-02 同一提交內容的確定性門禁 | G-01–05：hook、CI、index 內容與 warning 判斷不一致 | 前端為主；擬強制既有要求的正確落實 | staged／unstaged 分離案例、違規 fixture、hook／CI 執行紀錄 | 中；可能暴露既有問題，先量測與燃盡，不直接開新門禁 |
| P-03 機密與環境檔防護 | G-10 與公開來源整理風險；降低意外提交 | 兩端；擬強制保護、工具選型另議 | `.env.*`／範本／敏感 fixture 測試、人工脫敏清單 | 低至中；評估誤報及既有檔案，不能以掃描未命中保證安全 |
| P-04 品質門檻的可證明性 | G-06–09：test／coverage／Sonar／hook 含義不同 | 後端為主；擬強制精確報告，門檻數值維持原要求 | 綁定 lifecycle／CI 證據，查 excluded範圍、遠端 required checks | 中；可能需遠端權限，不能由本地配置推定已生效 |
| P-05 API 契約與相容性驗證 | 已有 OpenAPI／生成 API，仍有過期使用範例 | 兩端；建議先做契約差異報告，阻擋式升級另核准 | 固定 OpenAPI 產物、生成 diff、前後端契約測試 | 中；需規劃雙端發布順序，不默默推翻既有一刀切路由政策 |

## 後續考慮

| ID／主題 | 問題與效益、證據 | 範圍／擬定等級 | 驗證方式 | 成本／遷移影響 |
| --- | --- | --- | --- | --- |
| P-06 依賴與供應鏈 | 後端 AI 合約已有 action pinning／信任邊界要求，兩端有 lock／Maven 依賴；需建立更新責任與漏洞處理時效 | 兩端；先建議盤點，再決定強制政策 | 依賴清單、更新／漏洞演練、第三方授權與 SBOM 可行性 | 中；工具／誤報／私有 registry 相容成本待估 |
| P-07 測試策略與分層回歸 | 已有 Maven／Vitest，但尚未證明關鍵跨端流程、整合與 E2E 的完整範圍 | 兩端；先建議風險式測試矩陣，不直接新增共同覆蓋率 | 關鍵流程、失敗路徑、測試分層與耗時報告 | 中至高；維持單行程本機資源限制，CI 配置另議 |
| P-08 可及性與互動品質 | 根前端規範定義 UI 元件，但未定義可及性驗收 | 前端；擬先建議，目標等級待定 | 鍵盤／焦點／讀屏人工案例及自動掃描 | 中；可能涉及現有頁面與元件，不推定已違反尚未制定的標準 |
| P-09 效能預算與取消生命週期 | 已有前端 cleanup／按需載入、後端分頁／串流，尚無跨端量化預算 | 兩端；先建議量測，門檻待基線 | API p95、bundle、互動指標、SSE 取消／斷線及記憶體趨勢 | 中；需代表性資料，不捏造適用全部模組的閾值 |
| P-10 可觀測性與營運驗收 | 後端已有 tracing／Loki／韌性設計，但不是所有要求都已形成跨端驗收矩陣 | 兩端；先建議；敏感資料不得記錄仍依既有規則 | trace 串接、錯誤關聯、警報與降級演練、敏感日誌負案例 | 中至高；不搬部署實址／憑證，營運門檻需情境資料 |
| P-11 發布／回滾與審查責任 | 兩端有各自 CI 與 ADR；共通變更責任、發布證據與例外到期需明確化 | 兩端；先建議工作流驗證，不自動更改 branch protection | 以一次小型升版演練核對審批、來源、例外與回復流程 | 中；公開遠端操作須另授權，資料庫 rollback 不等於無資料損失保證 |

## 目前不適用

| 項目 | 理由與重新評估條件 |
| --- | --- |
| 統一 Maven／pnpm、共用全套 ESLint／Java 檢查配置 | 技術不同，不是規範衝突；若出現可共用的具體語意規則再抽取 |
| 把兩端業務領域 CONTEXT／ADR 合成共同模型 | 本庫治理工程要求，不擁有業務概念；出現真正跨域治理模型需求再評估 |
| 自動追蹤最新版、立即接 CI／hooks 或集中執行建置 | 已選鎖定採用及初期離線檢查，不屬本次授權；經工具驗證及新決策後再議 |
| 立即導入監管合規或全套 SLSA／簽章認證門禁 | 未提供適用法規／供應鏈目標及成本證據；有明確外部要求時再立案 |

核准時請逐案補：核准者、日期、決定等級、驗收條件與遷移時程。未核准前不得把這份清單當 Code Review 的新增阻擋依據。
